# DASH-01 Walker v2 — implementation contract (CPU reference, 2026-09-09)

Ground truth: the "DASH-01 Walker v2" artifact (rev 2026-09-09). This file states what the CPU
stack in `walk_mit/` actually implements, so a second implementation (the GPU port) can be held
to the same policy-facing interface. Anything not listed here is an implementation detail; a
policy trained on either side must load and act identically given these.

## Timing

| item | value |
|---|---|
| physics | MuJoCo, 1 kHz (`dash01_v2.xml`, `implicitfast`) |
| control | 100 Hz = 10 substeps per tick (`control_decimation=10`) |
| episode | 60 s = 6000 ticks (`episode_s`), fall/finish terminate earlier |
| discount | γ 0.995, λ 0.95 (2 s horizon) |
| reward scale | per-tick sum × `control_dt/0.02` = ×0.5 (rate invariance), floored at −0.5 pre-terminal; fall −100, finish +100 |

## Action — 50 dims, all in [−1, 1] (`gait_v2.Layout(3)`)

| idx | field | latched | notes |
|---|---|---|---|
| 0:7 | S cam a0,a1,b1,a2,b2,a3,b3 | yes | weights `w_k ∝ 1/√k` normalised to Σ1 (`fourier_gait._weights`), ±`cam_amp` 0.45 clip |
| 7:14 | S thigh | yes | ±`thigh_amp` 0.45 |
| 14:21 | S hip_roll | yes | ±`roll_amp` 0.20 |
| 21:28 | kp(φ) profile | yes | series → exp map, ×2.5 / ÷3 |
| 28:35 | kd(φ) profile | yes | series → exp map, ×1.0 / ÷4 (soften-only) |
| 35 | freq_raw | yes | linear → [0.5, 5.0] Hz (`v2b_*`: [1.5, 4.0] Hz, neutral 2.75 Hz unchanged) |
| 36:39 | roll reflex kp, kd, bias | yes | u = 0.5·kp·roll + 0.1·kd·roll̇ + 0.2·bias, enters hip_roll **(+,+)** |
| 39 | Δ (lag) | yes | × `delta_max_rad` 0.6; right leg reads S at φ − π − Δ |
| 40 | s (stride asym.) | yes | g_L = 1+s, g_R = 1−s |
| 41:44 | o cam, thigh, hip | yes | × (0.06, 0.06, 0.15) rad, enters both legs **(+,+)** |
| 44:50 | residual r0..r5 | no | × `residual_scale` 0.20 rad (`v2b_*`: 0.10 rad), actuator order hip_roll_L cam_L thigh_L hip_roll_R cam_R thigh_R |

Generator (per family, A = family amplitude, n = per-episode stance nominal = keyframe ctrl):

    u_L(φ) = n_L + (1+s)·clip(A·S(φ), ±A) + o
    u_R(φ) = n_R − (1−s)·clip(A·S(φ−π−Δ), ±A) + o
    thigh  += ∓ u_p  (fixed pitch reflex, u_p = −clip(1.0·grav_x + 0.1·pitch_rate_lp, ±0.25),
                      pitch_rate_lp = EMA(α 0.9 per tick) of gyro-y — retuned for the no-EMA drive)
    hip    += u      (learned roll reflex, both legs +)
    target  = u + 0.20·residual, clipped to ctrlrange, slew-limited to the no-load speed

Gains: each leg reads kp(φ)/kd(φ) at its own phase; multipliers on the plant's (DR-drawn) kp/kv.

Latch: the 44 spec entries reach the generator **only** on a tick whose observation carries
`commit = 1`; on every other tick they are discarded. `commit` is set when the clock wrapped while
advancing to this tick (free-running, or carried across 2π by the contact resync); at reset it is 1.

Library variant (`spec_source="library"`): action = [residual 6, latched mods 3 (Δf/f, amplitude,
lift) × 0.2]; the spec comes from the library entry (+ box draw) and the Raibert prior at each
commit (`raibert.py`).

## Plant (`model/dash01_v2.xml`, generated by `model/make_v2_plant.py`)

* loop closure: `<connect>` solref 0.002 / solimp 0.999–0.9999 (rigid); 20 DOF
* series spring: prismatic joint `leg_spring_L/R` along the vertical foot strut (ankle → toe),
  k 13.06 kN/m axial, b 75.4 N·s/m, calibrated to a one-leg stance sink of 5.0 mm at 1 BW
  (4.98 / 5.03 mm; DR ±50 % → 9.7 / 3.4 mm). The artifact's pushrod-tip location cannot produce
  the 5 mm (the rod carries 10–45 N of the 148 N at stance); `make_v2_plant.py --spring rod`
  keeps that variant. The GPU port fitted its own foot spring to the same 5.00 mm, so the two
  plants meet on the artifact's verification criterion, not on a stiffness number.
* drive: `<position kp=200 kv=5>` (hip roll 120/4), joint armature **0** on the six actuated
  joints (Bode fit, `model/drive_fit.json`), **no** EMA target filter, transport delay on
  (target, kp, kd) at 1 ms granularity: 12 ms nominal, U[6, 18] ms per episode
* torque/speed: forcerange 144.5 / 61.2 N·m, no-load command cap (22.01 / 10.30 rad/s),
  back-EMF clamp at 48 V (R 0.229 / 0.665 Ω)
* thermal: per motor θ̇ = ((τ_rms/τ_cont)²/c − θ)/45 s, τ_cont (23, 55, 55, 23, 55, 55) N·m,
  θ0 ~ U[0, 0.7], c ~ U[0.8, 1.2]
* ankle: rigid (lock equalities), shin −0.209 kg (carbon tube)
* clock resync: κ ~ U[0.3, 0.7], window ±0.15 cycle, habit EMA 5 cycles, κ = 0 for 3 cycles
* DR: mass 0.12 / body 0.15 / inertia 0.25 / CoM 0.03 m / friction 0.4–1.3 / kp 0.20 / kv 0.25 /
  torque 0.12 / joint damping 0.30 / tilt 5° / loop sites 1.5 mm / homing 2° / IMU 2° / IMU dropout 0.001
* disturbances: pushes |dv| U[0.3, 0.6] m/s every ~4 s (random direction, free axes), wind
  U[−30, 30] N body x and y per episode, 30 N gusts of 1 s every 5–10 s, trips 0.0008/tick
* all adversity rides the DR curriculum scale (0 → 1 over 60 M, gated at ep_len 600)

## Reward terms (per tick, before the ×0.5 rate scale)

Unchanged from `sprint_m6_lim2`: fwd_speed (2.0·clip(vx, ±3) × uprightness), time −0.5, stop,
overrun, foot_slip, air_time, stance_time, clearance, phase_contact, step_rate (0.20), duty_sym
(8.0), torque/motor_vel/energy (ramped), action_rate 0.1, upright 5, vz 0.5, lat_vel 1,
ang_xy 0.05, angmom 0.2, stance 50, hip_roll 3, assist_pen.
Changed / new:

| term | formula |
|---|---|
| yaw_rate | −3.0 · (LP yaw rate, true gyro, τ 0.7 s)² |
| height | −2.5 · max(0, 0.81 − z)² (one-sided) |
| residual / residual_rate | −0.10·‖r‖² / −0.02·‖r − r_prev‖² |
| spec_cycle | −0.5 · ‖S_k+1 − S_k‖² on the commit tick only (0 on the first commit) |
| knob | −0.02 · ‖(Δ, s, o_cam, o_thigh, o_hip)‖² (raw) every tick |
| thermal | −20 · Σ max(0, θ_i − 0.85)² |
| lane | −2.0 · max(0, |y| − 0.25)² |
| coef_rate, imp_rate | 0 (replaced by spec_cycle; gains are latched) |

Every penalty term is floored at −2.0 (`penalty_term_cap`).

## Networks and losses

* estimator 377→128→64→3 (supervised MSE vs tail[0:3] after each rollout, Adam 1e-3, 2 epochs × 4096, detached into the actor)
* actor 380→256→256→50 + state-independent log σ (clamped ≤ 0, annealed to log 0.25)
* critic 402→256→256→1
* PPO: 64 envs × 288 steps, batch 4096, 4 epochs, lr 3e-4→1e-4, clip 0.2, target KL 0.03, ent 0.01→0
* log-prob and entropy of the 44 latched dims are multiplied by `commit` (`masked_policy.py`)
* symmetry loss (`sym_ppo.py`): 0.5·‖k(M_o s) + k(s)‖² on the five knobs + 0.5·‖r(M_o s) − M_r r(s)‖²
  on the residual, with M_o from `DashEnv.mirror_perm_sign()` (raw obs mirrored, re-normalised)

## Curriculum

S1 = `v2_s1` (base x, z, pitch free), S2 = `v2_s2` (all six free), identical widths; warm S1→S2
with `--warm-start` (log σ re-inflated). Ramps at 100 Hz: sprint line 25→100 m over 60 M,
stance ratio 0.65→0.42 over 120 M, efficiency 0→1 over 120 M, pitch assist 100 N·m/rad fading
over 30 M, DR 0→1 over 60 M gated at ep_len 600, jitter/drop after ep_len 800, entropy anneal
deadline 12.5 M, 300 M total.

## Readout-1 deltas — the `v2b_*` presets (2026-09-10)

The first v2_s1 chains (JED 66421817/8, artifact-literal) were measured at 33 M with
`walk_mit/monitor/greedy_peek.py` (commit-tick statistics, greedy episodes at the run's DR scale
and on the nominal plant). What they committed: every Fourier family at rms 0.93–1.0 (bang-bang
spec), knobs at the rails, the clock at exactly 5.00 Hz on 100 % of commits, the residual 60–67 %
of the joint-target deviation with 45 % of ticks at its bound — THE RUNNER's pathology inside the
latched design. Both seeds regressed from ep_len ~700 at 19 M to ~150 by 33 M while the
clock-driven assist fade, the DR ramp (gate 600) and the std anneal (opened at 92 k steps by the
swing-fraction gate, which reads 0.4 on a falling robot) overlapped. `v2b_*` keeps the plant, the
obs and action layout and the reward set, and changes only:

| knob | v2 (artifact) | v2b | why |
|---|---|---|---|
| `gait_freq_hz` | (0.5, 5.0) | (1.5, 4.0) | no 5 Hz max-commit rail, no 0.5 Hz freeze; neutral 2.75 Hz kept |
| `residual_scale` / `w_residual` | 0.20 rad / 0.10 | 0.10 rad / 0.20 | half the per-tick authority, twice the bill |
| pitch assist fade | clock, from step 0 | `pitch_assist_gate_ep_len` 600, then 30 M monotonic | fade the wheel once the policy runs on it |
| entropy / std anneal gate | swing_frac 0.13 | + `ent_gate_ep_len` 600, deadline 40 M | a falling robot has both feet airborne |
| DR gate / jitter gate | 600 / 800 | 1200 / 1200 | harden a runner, not a stander |

The GPU port must mirror the first two rows to stay in parity with a `v2b` policy; the three
curriculum rows are training-side only. Evaluation harness fixes that came with the readout:
`evaluate.build` now restores `dr_scale` and `pitch_assist` from curriculum.json (the env builds
its randomizer at full width), and the train-time clock diagnostic counts commit ticks only.

## Readout-2 deltas — the `v2c_*` presets (2026-09-10)

`v2b_s1` reached a stochastic ep_len of 1466–2421 at 23 M and, re-evaluated with the fixed probe,
**finished 3/3 greedy 100 m dashes on the nominal plant at 1.8–1.9 m/s** (pitch assist still at
0.8 of its 100 N·m/rad). It then collapsed to ep_len ~25 by 50 M while the assist faded to 0.2,
the std annealed 0.77 → 0.4 and DR / jitter ramped — all clock-driven once their gates had opened
(`curriculum_retreat_frac` was 0). `walk_mit/monitor/mean_bounds_probe.py` on the 23 M policy:
68–79 % of the spec means and 53–60 % of the residual means lie outside [−1, 1] (median |μ| ≈ 2,
p90 ≈ 3.9). The DiagGaussian is sampled unbounded and clipped by the env, so once a rail pays every
mean beyond it earns the same clipped sample: the "bang-bang spec", the clock parked on its
ceiling and the saturated residual are all clip(μ) of drifted means, and greedy clip(μ) no longer
equals the effective action E[clip(μ+ε)] the policy was trained on.

| knob | v2b | v2c | why |
|---|---|---|---|
| `w_bound` (SymPPO bounds loss, w·mean(relu(|μ|−1)²)) | — | 1.0 | keep the means inside the box; logs `train/bound_loss`, `train/mu_out_frac` |
| `curriculum_retreat_frac` | 0.0 | 0.7 | DR / jitter ramps advance only while ep_len ≥ gate, hold between, retreat below 0.7·gate |
| `max_log_std` | 0 (std ≤ 1.0) | ln 0.7 | the pre-anneal policy is not a noise machine |
| `w_assist_penalty` | 0 | see config | the round-4 anti-crutch term: a fading wheel alone breeds dependence |

The GPU port is unaffected by these rows (all training-side); parity for a `v2c` policy is on the
`v2b` action/obs rows above. Probe fixes that came with this readout: `greedy_peek.py` no longer
calls `_workspace_violation()` from its hook (that method advances the per-foot grace timer on
every call, so the hook halved the 0.10 s grace and killed healthy gaits at 13–19 ticks — every
"ws at reset" verdict before 2026-09-10 08:40 was the probe), and `mean_bounds_probe.py` reports
the pre-clip means per action group.

## Parity fixture

`golden_v2.py` records/checks a deterministic trace (`golden/*.npz`): commit flags and the live
spec must be **exact**, observations within 1e-4, rewards within 1e-3 over the recorded ticks.

## CPU / GPU parity protocol

1. **Environment level** — the GPU env replays `golden/v2_s1_clean_seed0.npz` (and the library
   variant fixture) with the recorded action sequence from the recorded initial state and runs
   `golden_v2.py --check`: commit flags and the live spec must match exactly, observations to
   1e-4, rewards to 1e-3. Physics engines differ, so if the trajectories diverge beyond the
   tolerance after the first few ticks, compare the per-term rewards (`terms`, `term_names`) and
   the command the plant received (`ctrl_seen`) tick by tick to localise the difference.
2. **Throughput** — `bench_v2.py --n-envs 64 --n-steps 288 --subproc` on one JED node (the CPU
   figure) against the GPU port's env-steps/s for the same rollout size; report both as
   "hours per 300 M steps".
3. **Policy level** — same preset (`v2_s1`), same seed, same PPO hyperparameters, same step
   budget on both sides; then greedy evaluation of both checkpoints with `tools/eval_dash_xy.py`
   (16 dashes, paired seeds 1000+) and `gait_diag.py` (frequency rails, residual saturation,
   contact duty per foot). Two stochastic optimisers on different physics will not produce
   bit-identical weights; "the same policy" means the same dash time distribution, the same
   two-legged duty (both feet > 0.10), and the same rails/saturation diagnostics within the
   paired-seed spread. Cross-load each side's checkpoint into the other's env (the interface is
   identical) as the decisive test: a policy trained on one must run on the other.
